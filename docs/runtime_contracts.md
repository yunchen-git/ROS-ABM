# Runtime Contracts

This document defines current behavior that downstream analysis depends on.

## Output folder layout contract

Per run, outputs are written under:

- `<base_path>/<run_id>/`

Where:

- `<base_path>` is the launcher save root (currently set in `Model_run.py`).
- `<run_id>` is numeric and allocated by `CountDirectory.newDirect(...)` (for example `1.0`, `2.0`).

## Output filename contracts

Inside each run folder, runtime currently writes:

- `info.sim`
- `network<time>.gpickle` for each saved time point
- `<gradient_name>_<time>` for each extracellular gradient snapshot
- `<interC_name>_<time>` for each intercellular snapshot

Examples:

- `network0.0.gpickle`
- `H2O2e_0.0`
- `cAMP_0.0`
- `H2O2i_0.0`
- `Ca_0.0`

## Postprocess behavior contract

At completion of `Simulation.run(...)`, the runtime currently invokes both postprocess hooks:

- `read_gpickle.read_network(run_path, t0, tf)`
- `gradientImage.getGradientImages(run_path)`

This invocation behavior is treated as part of the current runtime contract.

## Required downstream assumptions

Downstream scripts and notebooks currently assume:

- run folders are numeric child directories under the chosen base path
- network snapshots are named `network<time>.gpickle`
- `info.sim` indexes saved files and stores platform/time/species header data
- species names remain stable (`H2O2e`, `cAMP`, `H2O2i`, `Ca`, etc.)
- postprocess image folders are generated by the existing hook path

## Current working directory (CWD) assumptions

Current runtime behavior relies on CWD:

- `Model_initialParameters.py` loads `new_populated.txt` using `os.getcwd()`.
- `Simulation.load_gene_expression_data()` references paths rooted from `os.getcwd()` (plus one absolute metadata path in current code).

Operational implication:

- Runs are expected to be launched from repository root unless paths are changed explicitly.

## Guardrail intent

Until an approved migration plan is executed, the items in this document should be preserved to avoid downstream breakage.
